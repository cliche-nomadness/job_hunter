## 2. 已完成课程速览（L1–L11，沉淀）

> 这 11 课已把"地基"打牢，是 v2.1 的信心来源：

- **Python 全基础**：语法/数据结构/OOP/模块化/异常/正则/切片（L1–L5 穿插完成）
- **数据与建模**：JSON 持久化、状态机（合法迁移/终态）、`ApplicationBook` 类封装（多前台复用）
- **AI 能力**：DeepSeek API（结构化 Prompt）、LangGraph 图编排（节点/条件边/`interrupt` 人机协同）
- **后端**：FastAPI（HTTP/路由/Pydantic）、REST API
- **第三方集成（飞书全流程）**：事件订阅、验证令牌、官方 SDK（`EventDispatcherHandler`/RawRequest）、长连接模式、message_id 幂等去重、事件前置权限
- **方法论沉淀**：读官方源码 vs 猜算法、官方文档是权威、至少一次投递必须幂等、YAGNI

## 3. 重构后的课程（L12–L15 详解）

### L12 · Playwright 浏览器自动化 + 岗位采集实战（★核心技能）

> 为什么独立成课：**Playwright 是本模块的核心技能，你要"掌握"而非"顺手用"**；
> 岗位采集是已验证的真实教材（Moka 全链跑通），正好当实战案例。

#### 12.1 Playwright 入门（核心技能）

- **环境**：`pip install playwright` + **系统 Edge**（`channel="msedge"`）——Windows 免下载 Chromium；
- **导航与等待**：`goto` / `wait_until` / `wait_for_timeout`（SPA 渲染要等）；
- **选择器与文本**：`locator` / `get_by_text` / `inner_text`；
- **拦截响应**：`page.on("response")` 拿页面自发的结构化数据（岗位 id 藏 JS 时的钥匙）；
- **网络健壮性**：重试 + 加长超时 + 请求间停顿（国内站偶发超时的标配）。
- **产出**：自己写一个"打开 → 渲染 → 抓文本"的最小脚本。

#### 12.2 岗位采集实战（把 Playwright 用到真项目）

- 从公司官网 URL 抓岗位列表（标题 / 元信息 / 详情链接）；
- 进入详情抓 JD（`inner_text` + 正则标出"职位描述"区段）；
- **跨平台认知**：id 在 DOM（Moka，`#/job/{id}`）vs id 在 JS（zhiye，`jobAdId` UUID）→ 两种适配器；
- **产出**：整理成 `job_provider_moka.py`（列表 + JD 模块），喂给 L11 简历分析的 JD 来源。

> 附：自动进度同步（登录态抓"我的投递"）**延后并入 L13**（与部署同课，因需常驻定时；Playwright 技能完全复用）。

### L13 · 部署落地（7×24 常驻）

> 为什么先于工程化：**电脑关机 = 机器人下线 = 不算落地**。先让它 24 小时活着。

- **目标**：把 bot 部署到常开环境（云服务器最稳 / 常开旧电脑兜底）。
- **内容**：
  1. 云服务器开通（或常开机器准备）；
  2. Docker 化（app + 定时任务）；
  3. 进程守护（systemd / supervisor）+ 崩溃自启；
  4. 环境变量/密钥管理（脱离 `run_bot.cmd`）；
  5. （若回退 webhook 模式）域名 + 反代 + HTTPS。
- **验收**：重启/断电恢复后自动拉起；连续运行一周无人工干预。
- **意义**：L13 结束 = **功能级落地**（每天自动同步 + 7×24 常驻）。

### L14 · 工程化 + 求职补强

- **目标**：可靠性 + 简历就绪（两件事一起做）。
- **内容**：
  1. **PostgreSQL(+pgvector)**：JSON 文件 → 数据库（`ApplicationBook` 接口不变，只换底层——L5 的设计在这里兑现）；
  2. **Redis**：缓存/幂等/会话状态；
  3. **pytest 单元测试**（补 JD 缺口）：给状态机/ApplicationBook/命令解析写测试；
  4. **git + GitHub 开源**（补 JD 缺口，简历硬通货）；建议**提前到 L12 前**就 git init；
  5. 对象存储（简历版本/PDF）。
- **验收**：`pytest` 全绿；GitHub 仓库可克隆、README 完整；数据迁移无丢失。
- **意义**：L14 结束 = **工程级落地 + 简历就绪**。

### L15 · 增强（选做）

- 多站点 `JobProvider`/`ProgressProvider` 扩展（workflow 扇出）；
- 腾讯文档/石墨官方 API 适配器（替换 FileDrop）；
- **Agent 工具调用显式化**（LangGraph tools，补 JD 高频点）；
- PDF 渲染（Playwright/WeasyPrint，补 L11 延后的账）。

## 7. 节奏与建议

**排期（按每周 10 小时）**：

| 课 | 预计耗时 |
|---|---|
| L11 收尾 | 1–2 天 |
| L12 岗位/JD 同步 + 自动进度同步 | 5–7 天（先 JD 后进度；含站点调试，风险最高的模块）|
| L13 部署落地 | 2–3 天 |
| L14 工程化+补强 | 4–6 天 |
| L15 增强 | 选做 |

**三个贯穿建议**：
1. **git 现在就 init**（不等 L14）——代码从第一天就该进版本控制，且 GitHub 链接是简历硬通货；
2. **自动同步优先于工程化**——它才是项目灵魂，先跑通闭环再谈数据库；
3. **RAG 不重复造轮子**——由你的 Dify/RAGAS 项目覆盖，校招虾专注 Agent 编排 + 自动同步 + 全栈。

**风险提示**：L12 是外部对抗模块（反爬/改版），**给足缓冲时间**；单站点 MVP 跑通即算成功，不要贪多站点。先 JD（公开页低风险）再进度（登录态高风险），先易后难。
