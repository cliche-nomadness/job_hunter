## 1. 遇到的最大困难：读取"仅查看、无复制权限"的腾讯智能表格

**背景**：校招虾要从一个腾讯智能表格（**他人所有、我只有查看权限、无复制权限**的校招汇总表）里读取"投递链接"字段，用于岗位批量采集。我是**个人开发者身份**。

**困难**：常规读取方式全被堵死——既不能复制/导出，又面临权限与平台门槛。

### 解决过程（四步探索，层层换通道）

1. **试 Playwright 页面抓取**（浏览器自动化）
   - 发现该表是 **Canvas 渲染**，`inner_text` 抓不到单元格；
   - 拦截前端接口发现数据是 **base64 → zlib → protobuf 三重编码**（`initialAttributedText.smartsheet` 字段是 `eJz...` 开头的压缩二进制）；
   - **判断**：逆向未公开的 protobuf schema 成本高、易失效——这条路放弃。

2. **试腾讯文档 Open API**（`get_records`）
   - 发现该 API 需要**企业认证开发者**才能「创建应用 + 开通 `scope.smartsheet` 权限」；
   - 我是个人身份，**连"创建应用"入口都没有**，报错 `scope.smartsheet` 权限不足；
   - **判断**：OAuth 应用流面向企业/合作伙伴，个人身份走不通。

3. **换思路——用现成的 workbuddy 读表**，并**反查其底层原理**
   - 发现 workbuddy 的底层是**腾讯文档官方 MCP 接口**（`docs.qq.com/openapi/mcp` + **MCP 专用 token**）；
   - **关键发现**：这个 **MCP 通道个人也可用**（在 `auth/mcp.html` 拿 MCP token，**不需要企业身份、不需要建 OAuth 应用、不需要 scope**）。

4. **直接复刻 MCP 调用**（JSON-RPC 2.0 `tools/call`）
   - 调 `smartsheet.list_records`（含 `file_id`/`sheet_id`/`view_id`），拿到**结构化 JSON**，`flatten_record` 拍平后直接取出"投递链接"字段；
   - **成果**：成功读取智能表格记录，对接岗位采集（`scrape_jobs.py`），完整链路 `表格 → 投递链接 → 岗位列表 + JD` 闭环。

### 方法论沉淀（面试加分点）

1. **页面数据加密/压缩 → 别反向破解，找官方通道**（逆向二进制是死路，MCP/API 才是正解）；
2. **平台 API 报"权限不足/scope" → 先怀疑"用错了鉴权通道/协议"**（REST vs MCP、OAuth access_token vs MCP 专用 token），而不是猜"文档没授权"——我之前就卡在猜错了方向；
3. **遇"个人/企业"门槛 → 找"个人版专属通道"**（MCP 就是个人可用的一条，绕开了 OAuth 应用流的三重墙）。

## 2. 一句话版本（30 秒口头）

> "当时卡在从一个**仅查看、无复制权限**的腾讯智能表格里读数据，而且是个人身份。试了页面抓取——发现是 Canvas 渲染 + 数据 base64/zlib/protobuf 三重加密，逆向不值得；试官方 Open API——发现要企业认证才能建应用开权限。最后我用现成工具 workbuddy 读表，反查它底层是**腾讯官方 MCP 接口**，而这个 **MCP 通道个人也能用**，我就直接复刻 MCP 协议拿到结构化数据。**教训是：平台报权限不足，先怀疑用错了鉴权通道，而不是文档授权。**"
