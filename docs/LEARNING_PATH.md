# 校招虾 · 零基础学习与建造路线

> 配套：[ARCHITECTURE.md](./ARCHITECTURE.md)（完整目标）、[TASK_BREAKDOWN.md](./TASK_BREAKDOWN.md)（工程拆解）
> 定位：给**没有 Python / 前后端基础**的你，一条"边做边学、真正掌握"的路线。
> 导师：DeepSeek Harness（DSH）——逐行讲解、留动手任务、答疑 review。

---

## 0. 现实预期

- **完整版难度**：FastAPI + LangGraph + PostgreSQL + 飞书 + PDF 渲染，对零基础是"陡坡"，即便有经验工程师也要几周。
- **核心风险**：直接照完整架构抄 → "看得懂、改不动"。
- **破解办法**：把项目拆成**阶梯**，每个阶段只引入一个陌生概念，先跑通业务再换重型武器。

---

## 1. 核心策略（5 条原则）

1. **先 CLI 后 Web**：先做命令行工具，再学 HTTP/FastAPI 接飞书。
2. **先 SQLite/JSON 后 PostgreSQL**：先零部署的存储，再换生产库。
3. **先脚本后图**：先用 `if/else` + 函数实现流程，再上 LangGraph 图。
4. **先"能跑"后"优雅"**：先让功能工作，再谈结构、抽象、测试。
5. **你动手，我讲解**：DSH 写代码时逐行讲"为什么"，你亲手改、亲手弄坏再修。

## 2. 阶段路线图

### 阶段 0：Python 打底（约 1–2 周）

**目标**：能写出一个"命令行投递记录本"（数据存内存，退出即丢）。

**最小知识点清单**（不需要全会，够用就行）：

| 知识点 | 用到项目哪里 |
|---|---|
| 变量、类型（str/int/list/dict）、循环、条件 | 一切 |
| 函数、类与对象 | 领域服务、Provider 抽象 |
| 虚拟环境 + pip + requirements.txt | 装依赖 |
| 读写文件（json/csv） | 简历、岗位表格 |
| 命令行输入输出（input/print、sys.argv） | CLI 版 |
| try/except | 处理表格脏数据 |
| （可选）pytest 最简用法 | 尽早养成测试习惯 |
| 调用一次 DeepSeek API | AI 能力的最小体验 |

**里程碑**：写一个脚本，能"添加投递 → 列出所有投递 → 更新某条状态"，数据用 list/dict 存内存。

### 阶段 1：CLI 最小可运行版（约 2–3 周）

**目标**：把校招虾**核心业务**在命令行跑通，**不碰**飞书/LangGraph/向量/PDF/Redis。

- 存储：**SQLite**（零部署，`sqlite3` 标准库即可）
- 功能：
  1. 录入投递、更新状态、列出进度（状态机先简化为几个状态）
  2. 从 **CSV 文件**导入岗位（对应未来"在线表格"）
  3. 调 DeepSeek：给一份简历 + 一个岗位 → 输出匹配意见
- 数据结构：沿用 `ARCHITECTURE.md` §6 的 `Application / Job` 简化版

**里程碑**：命令行里能完成「导入岗位 → 投递 → 更新进度 → AI 给简历意见」整条链。

### 阶段 2：接入飞书（约 2–3 周）

**目标**：把 CLI 换成飞书机器人。

- 学 FastAPI 最小概念：路由、请求体、响应、`uvicorn` 起服务
- 飞书开放平台：创建自建应用、事件订阅、验签、发消息、发消息卡片
- 把 CLI 每条命令映射成：飞书消息（文本）→ 意图 → 动作；卡片按钮 → 动作
- 内网穿透（ngrok/cloudflared）让飞书回调到本地

**里程碑**：飞书里发「投了字节后端」→ 机器人回确认卡片；发「我的进度」→ 进度卡片。

### 阶段 3：AI 编排（约 2 周）

**目标**：把"改简历"升级成 LangGraph 图。

- 学 LangGraph 最小概念：State、Node、Edge、工具调用、`interrupt`
- 流程：分析（匹配报告）→ 人工确认（卡片按钮）→ 改写 → 版本化保存
- 向量检索**后置**：先关键词搜索，跑通后再上 pgvector/BGE 向量

**里程碑**：针对某岗位，机器人先给匹配报告，点「确认改写」后产出新版简历。

### 阶段 4：工程化加固（持续）

- PostgreSQL(+pgvector) 换 SQLite
- Redis（幂等/限流）、对象存储（MinIO/S3）、PDF 渲染、Docker Compose 部署
- APScheduler 每日更新岗位任务
- 腾讯文档/石墨官方 API 适配器（替换 FileDrop）

## 3. "熟悉掌握"的 3 条铁律 + 自测清单

### 铁律

1. **费曼测试**：每个模块能用大白话讲给"不懂代码的朋友"听，才叫会了。
2. **弄坏再修**：每个功能故意改错一次（比如状态机允许非法迁移），再修回来。
3. **为什么清单**：每个模块写下"为什么这么设计"，答不上就回来问 DSH。

### 自测题（阶段结束时口头回答）

- 为什么阶段 1 用 SQLite 而不是 PostgreSQL？
- 为什么简历要"版本化"、改写要写 `ResumeEdit` 审计？
- 为什么"改简历"要用 LangGraph 的 `interrupt`，而不是一个普通函数？
- 为什么岗位入库要按 `source + source_row_id` 幂等？
- 什么是状态机的"终态"，为什么终态不可再推进？

## 5. 时间投入建议

| 每周投入 | 预计到"可用的飞书版" | 节奏建议 |
|---|---|---|
| 5–7 小时 | 约 8–10 周 | 稳扎稳打，别跳阶段 |
| 10+ 小时 | 约 4–6 周 | 可适度压缩阶段 0 |

**最重要的一句**：不要为了"快"跳过阶段 0/1 直接抄完整版。阶段 0/1 是你建立"改得动代码"能力的唯一捷径，跳过它等于亲手埋下"看得懂改不动"的雷。

## 6. 课程路线图与每日节奏

| 编号 | 内容 | 阶段 | 单课耗时 | 状态 |
|---|---|---|---|---|
| L1 | 命令行投递记录本 | 0+1 | 1–2h | ✅ 完成 |
| L2 | JSON 文件持久化 | 1 | 1–2h | ✅ 完成 |
| L3 | CSV 导入 + 调 DeepSeek | 1 | 2h | ✅ 完成 |
| L4 | 完整状态机 + 岗位筛选 + 简历 Markdown 结构化 | 1 | 2h | ✅ 完成 |
| L5 | 拆模块 + 用类(class)重构 | 1 | 2h | ✅ 完成 |
| L6 | FastAPI 入门（HTTP/路由） | 2 | 2–3h | ✅ 完成 |
| L7 | 飞书应用创建 + 事件订阅/验签 | 2 | 2–3h | ✅ 完成 |
| L8 | 飞书消息 + 交互卡片 | 2 | 2–3h | ✅ 完成 |
| L9 | CLI → 飞书机器人（端到端）★**可用的飞书版** | 2 | 3h | 🔄 进行中 |
| L10 | LangGraph 入门（State/Node/工具调用） | 3 | 2–3h | ✅ 完成 |
| L11 | 简历优化图（分析→确认→改写）★**AI 改简历**（PDF 延后 L14）| 3 | 3h | ✅ 完成 |
| L12 | Playwright 浏览器自动化 + 岗位采集实战 ★**核心技能** | 3 | 3–4h | ✅ 完成 |
| L13 | 部署落地（7×24 常驻 + 每日自动同步岗位）| 4 | 2–3 天 | 🔄 进行中 |
| L14 | 工程化 + 求职补强（pytest/git+GitHub/PostgreSQL）★**简历就绪** | 4 | 4–6 天 | 🔄 进行中 |

**节奏结论**：

- 平均 **1 课/天（约 2 小时）** 是保质节奏。L1–L5 简单，可 1–2 课/天；L6 之后（飞书/LangGraph/工程化）一课通常要 **1–2 天**，因为涉及外部平台配置，卡点多。
- 按每周 10 小时：到 L9（可用的飞书版）约 **3–4 周**；到 L11（AI 改简历完整）约 **4–5 周**；到 L14（生产化）约 **6–8 周**。
- **"按质"的门槛**：每课过 3 条铁律（费曼/弄坏再修/为什么清单）+ DSH review 通过，才进下一课。**宁可一课做两天，不一天刷三课**——刷课快，但"看得懂改不动"的债要加倍还。

**实际进度复盘（L1–L8 完成后校准）**：

- L1–L6（CLI + FastAPI）实际节奏**符合甚至快于计划**——都是自研概念，无外部依赖。
- L7–L8（飞书）实际耗时**为计划的 3–5 倍**——第三方平台集成的隐性成本（验签算法、事件前置权限、免费隧道 3 秒超时、SDK API 差异、重复投递去重），与个人能力无关，谁做都要踩。
- **重估剩余**：L9 1–2 天；L10 2–3 天；L11 2–3 天；L12–L14 各 1–2 天 → 到 L14 约 **4–6 周**（若再遇平台级大坑则 6–8 周）。
- **判断**：L9 之后全为"自研"内容（LangGraph/工程化），**速度将回升**；近期的"慢"源于飞书平台本身，不是学习能力问题。
